# 仓库组织与模块边界

本仓库是 pnpm workspace 中的模块化单体。workspace package 是代码所有权和依赖边界，不是独立部署的微服务；API 与 Web 是应用进程，Packages 由应用组合根装配。

## 顶层目录的职责

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `apps/api` | Hono 宿主、HTTP 中间件、组合根、进程启动、迁移和一次性 provisioning 入口 | 领域规则、重复的 schema 或通用包注册器 |
| `apps/web` | 浏览器路由、页面、feature、Query hooks、浏览器 RPC client | Better Auth server、Drizzle 查询、数据库连接 |
| `packages` | Auth、Database、Jobs、Logging、System、Todos 等可复用能力与领域边界 | 进程级部署编排、跨模块组合根 |
| `container` | 应用镜像、Compose 服务、PostgreSQL 初始化脚本 | 本地开发进程逻辑、业务代码 |
| `scripts` | 开发命令编排、测试 runner、文档生成工具 | 领域 service、运行时业务 API |
| `docs` | 架构、指南、测试与部署文档、API reference 生成配置 | 第二份模块 README 正文 |

## 模块依赖方向

| 所有者 | 可以依赖 | 不应依赖 |
| --- | --- | --- |
| Web | 浏览器端 Auth client、业务模块导出的 route type、Hono client | API 完整 `AppType`、Auth server、Database、Drizzle、Node-only adapter |
| API | Auth server、Database、Jobs adapter、Logging、业务模块 | 由下层包反向依赖 API |
| Auth | Better Auth、Database schema/connection、共享 contracts | Todos 等具体业务查询、HTTP 组合根 |
| Todos | Auth contracts、Database schema/租户事务、Hono/Zod | Better Auth server、API bootstrap、浏览器代码 |
| Jobs | BullMQ adapter、Zod task contracts、Logger port | API 业务路由、所有业务任务的隐式发现 |
| System | Hono、Zod、Logger port 和注入的探针 | 创建 Database client、依赖具体业务模块 |
| Logging | LogTape 和进程级输出能力 | Auth、Todos、Jobs 等业务实现 |
| Database | Drizzle、PostgreSQL、schema 和 migration | Auth、Todos、API 等上层模块 |

依赖总体从应用流向能力包，再流向基础设施。Auth contracts 可供业务包使用类型，但不把认证实现或数据库访问反向塞进业务层。API 是唯一服务端 HTTP 组合根；子模块通过具体的 `setupXxxApp(app, options)` 注入宿主并返回链式 Hono app。

## 新代码放在哪里

| 变化 | 放置位置 | 示例 |
| --- | --- | --- |
| HTTP 中间件、路由挂载顺序、跨模块权限策略 | `apps/api/src/app/` | Hono composition、CORS、request ID |
| API 自有 HTTP 功能 | `apps/api/src/features/` | Jobs Admin 与 Diagnostics Log Stream |
| 进程配置 | `apps/api/src/config/` | API、Worker、migration、admin provision 各自解析配置 |
| 进程资源的创建/关闭及运行基础设施 | `apps/api/src/runtime/` | API server、环境加载、listen、telemetry |
| 可执行进程的顶层副作用 | `apps/api/src/entrypoints/` | API、Worker、migration、admin provision |
| 可复用业务规则和输入合同 | `packages/<domain>` | Todos schema、service、repository |
| 表结构、RLS、角色权限和正式迁移 | `packages/database` | Drizzle schema 与 SQL migration |
| 业务 Job 定义 | 拥有该业务的领域模块；当前示例在 Jobs 合同入口 | Zod 输入、processor、依赖工厂 |
| 队列连接、worker 生命周期、Bull Board 和 BullMQ migration | `packages/jobs` | server/worker/migration 子路径 |
| 路由配置和页面组合 | `apps/web/src/routes` | 路由入口、loader、route guard |
| 用户流程和服务端状态访问 | `apps/web/src/features/<feature>` | 登录/Todo hooks、表单行为 |
| Web 共享基础 client 和错误解析 | `apps/web/src/lib` | Hono client、API error |
| 被多个 UI 功能复用的纯展示组件 | `apps/web/src/components` | 不持有租户查询或路由副作用的组件 |

只有存在真实的复用边界或独立所有权时才新增 workspace package。单一消费者的页面逻辑留在 Web feature；HTTP 组合留在 API；数据库 adapter 不因一个业务表而额外拆包。复杂度增加时，再按现有职责把 schema、service、repository 和 route 分开。

## Package 入口与文件结构

```text
apps/
  api/src/       app、features、config、runtime、entrypoints
  web/src/       routes、features、components、lib
packages/
  <module>/src/  module public entry、contracts、implementation、tests
container/       Dockerfiles、Compose、PostgreSQL initialization
scripts/         launch/test/documentation tooling
docs/content/    hand-authored architecture and guide pages
```

API workspace 同时容纳 API、Worker、migration 和 admin provision 进程，以共享依赖与单一应用镜像；进程边界由 `entrypoints/` 和各自的 config 明确表达。`app/` 是 HTTP 组合根，`features/` 只放由 API 拥有的 HTTP 功能。业务规则仍归 `packages/<domain>`，队列 adapter 归 Jobs package。

公共入口只暴露消费者需要的能力。Auth 使用 `./server` 和 `./client` 分离运行环境；Jobs 使用 `./server`、`./worker`、`./migration` 分离 adapter；Web 只导入 System/Todos 等功能自己的 route type。不要从模块根入口泄漏 `pg`、BullMQ 或服务端实现类型，也不要为了内部文件建立大量 export subpath。

## 文档归属

根 `README.md` 负责仓库入口和快速启动；每个 app/package 的 `README.md` 是模块唯一正文来源；Rspress 的 `docs/content/modules/*.mdx` 和项目概览由同步脚本生成。架构、配置、测试、部署指南由 `docs/content/architecture` 和 `docs/content/guide` 手工维护。修改模块职责时更新对应 README，再运行 `pnpm docs:generate`，不要直接编辑生成页面。

## 运行时边界

本地完整开发使用 `just dev`；基础设施和 schema 已准备好时使用 `just dev-only`；`just launch*` 是旧入口兼容别名。生产形态 Compose 使用同一应用镜像运行 API、Worker、迁移和一次性管理员 provisioning。API/Worker/provision 使用 `DATABASE_RUNTIME_URL`，迁移使用 `DATABASE_MIGRATOR_URL`；应用 runtime 不持有 DDL 或初始管理员密码。数据库与模块行为详见各自 README 和[配置指南](/guide/configuration/)。
